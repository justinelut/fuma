# Docker Compose

The repository Compose file runs the same provider-neutral services used by hosted deployments: PostgreSQL 17, Redis, S3-compatible MinIO, and the Next.js web application.

## Prerequisites

- Docker Engine 20.10+
- Docker Compose 2+
- 4 CPU cores, 8 GB RAM, and 50 GB available disk

## Configure

```bash
git clone https://github.com/onlook-dev/onlook.git
cd onlook
bun install
bun run setup:env
```

At minimum, configure `CSB_API_KEY` and `OPENROUTER_API_KEY` in `apps/web/client/.env`. Compose provides internal `DATABASE_URL`, `REDIS_URL`, and MinIO variables. Replace the local Better Auth and MinIO secrets for any shared deployment.

## Start and migrate

```bash
docker compose up -d postgres redis minio
docker compose run --rm web-client bun --cwd packages/db db:migrate
docker compose up -d web-client
```

The migration command is a pure Drizzle runner. It creates the domain and Better Auth tables and verifies the identity foreign key and absence of legacy RLS.

## Verify

```bash
docker compose ps
curl http://localhost:3000
curl http://localhost:9000/minio/health/live
```

- Application: `http://localhost:3000`
- MinIO API: `http://localhost:9000`
- MinIO console: `http://localhost:9001`
- PostgreSQL: `localhost:5432`
- Redis: `localhost:6379`

## Production notes

Use unique credentials, TLS, private service networking, persistent-volume backups, and external secret management. Run `bun db:migrate` once per release before starting new web replicas. For K3s, use internal service addresses such as `postgres.<namespace>.svc.cluster.local`, `redis.<namespace>.svc.cluster.local`, and `minio.<namespace>.svc.cluster.local`.
