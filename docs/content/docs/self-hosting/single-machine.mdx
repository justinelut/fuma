# Single Machine Deployment

Install PostgreSQL 17, Redis, and MinIO locally or point Onlook at managed equivalents. The web process never needs database superuser credentials or direct browser access to MinIO.

## Setup

```bash
git clone https://github.com/onlook-dev/onlook.git
cd onlook
bun install
bun run setup:env
```

Configure these server-side values in `apps/web/client/.env`:

```properties
DATABASE_URL=postgresql://onlook:<password>@127.0.0.1:5432/onlook
BETTER_AUTH_SECRET=<unique-random-secret-at-least-32-characters>
BETTER_AUTH_URL=https://onlook.example.com
NEXT_PUBLIC_SITE_URL=https://onlook.example.com
OBJECT_STORAGE_ENDPOINT=http://127.0.0.1:9000
OBJECT_STORAGE_REGION=us-east-1
OBJECT_STORAGE_ACCESS_KEY_ID=<minio-access-key>
OBJECT_STORAGE_SECRET_ACCESS_KEY=<minio-secret-key>
OBJECT_STORAGE_BUCKET=onlook
REDIS_URL=redis://127.0.0.1:6379
```

Add `CSB_API_KEY`, `OPENROUTER_API_KEY`, and optional provider keys from `.env.example`.

## Migrate and build

```bash
bun db:migrate
bun --filter @onlook/web-client build:standalone
bun --filter @onlook/web-client start:standalone
```

`bun db:migrate` uses Drizzle migrations and is safe to rerun. Back up PostgreSQL and MinIO before each production upgrade.

## OAuth

Set provider credentials and callbacks as described in [OAuth Setup](/self-hosting/oauth-setup). Terminate TLS at a reverse proxy and ensure `BETTER_AUTH_URL` exactly matches the public origin.
