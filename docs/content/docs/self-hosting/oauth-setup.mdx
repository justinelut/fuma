# OAuth Setup

Better Auth owns OAuth state, callbacks, user linking, and sessions under `/api/auth`.

## GitHub

1. Create an OAuth App in [GitHub Developer Settings](https://github.com/settings/developers).
2. Set the homepage to your application origin.
3. Set the callback URL to:
   - Local: `http://localhost:3000/api/auth/callback/github`
   - Production: `https://onlook.example.com/api/auth/callback/github`
4. Configure:

```properties
GITHUB_CLIENT_ID=<client-id>
GITHUB_CLIENT_SECRET=<client-secret>
```

## Google

1. Create a Web OAuth client in [Google Cloud Console](https://console.cloud.google.com/apis/credentials).
2. Add these authorized redirect URIs:
   - Local: `http://localhost:3000/api/auth/callback/google`
   - Production: `https://onlook.example.com/api/auth/callback/google`
3. Configure:

```properties
GOOGLE_CLIENT_ID=<client-id>
GOOGLE_CLIENT_SECRET=<client-secret>
```

## Required Better Auth values

```properties
BETTER_AUTH_SECRET=<unique-random-secret-at-least-32-characters>
BETTER_AUTH_URL=https://onlook.example.com
NEXT_PUBLIC_SITE_URL=https://onlook.example.com
```

`BETTER_AUTH_URL` and `NEXT_PUBLIC_SITE_URL` must share the exact public origin. Production cookies are host-only, secure, HTTP-only, and SameSite=Lax.

## Troubleshooting

- A redirect mismatch means the provider callback does not exactly match `/api/auth/callback/<provider>`.
- A provider button is enabled only when both its client ID and secret are configured.
- OAuth users are linked by provider account ID and normalized email in the hosted PostgreSQL Better Auth tables.
