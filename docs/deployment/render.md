# Render Deployment

Render runs Instatic from the published image with managed Render PostgreSQL and a persistent disk for uploads.

---

## TL;DR

Use the checked-in PostgreSQL Blueprint:

```txt
docs/deployment/render/postgres/render.yaml
```

It provisions an image-backed web service, a persistent app disk, and a managed PostgreSQL database.

## Blueprint contract

The Blueprint configures:

```txt
Image=ghcr.io/corebunch/instatic:latest
PORT=10000
DATABASE_URL=<Render internal PostgreSQL connection string>
UPLOADS_DIR=/app/storage/uploads
STATIC_DIR=/app/dist
INSTATIC_SECRET_KEY=<generated by Render>
Health check path=/health
```

The database connection comes from the Blueprint's `fromDatabase` reference with `property: connectionString`. Keep the database private (`ipAllowList: []`) unless a restricted administrative connection is explicitly required.

Render auto-injects `RENDER_EXTERNAL_URL`; Instatic uses it as the default CSRF public origin. Set `PUBLIC_ORIGIN` explicitly when adding custom domains. `TRUSTED_PROXY_CIDRS` is optional and only controls forwarded client-IP attribution.

The app runs migrations at startup. Do not add a separate migration command.

## Template repository

Render's deploy button reads `render.yaml` from a Git repository. The dedicated PostgreSQL template repository should copy `docs/deployment/render/postgres/render.yaml` to its root:

```txt
corebunch/instatic-render-postgres
```

A template README may expose:

```md
[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/corebunch/instatic-render-postgres)
```

Use `runtime: image` so Render pulls the release image instead of rebuilding the public repository.

## Persistence and backups

- Content and application state live in managed Render PostgreSQL. Enable the backup/PITR policy required by your plan and keep independent `pg_dump` files when provider-independent recovery is required.
- Media, fonts, plugin packages, and published artefacts live on the persistent app disk under `UPLOADS_DIR`; back up that disk separately.

See [backup-restore.md](backup-restore.md).

## Troubleshooting

| Symptom | Check |
|---|---|
| Database connection fails | `DATABASE_URL` must use `fromDatabase` and the internal connection string. |
| Health check fails | `PORT=10000` and health path `/health` must match the service. |
| Uploads disappear | The disk must be mounted at `/app/storage` and `UPLOADS_DIR` must be below it. |
| Setup/login reports invalid origin | Use the exact `RENDER_EXTERNAL_URL`, or add custom origins to `PUBLIC_ORIGIN`. |
| Encrypted credentials or MFA fail | Confirm `INSTATIC_SECRET_KEY` exists and has not rotated. |
| Render builds source unexpectedly | The Blueprint must use `runtime: image`. |
