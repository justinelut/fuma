# Generic Next.js source portability

## Status and scope

This reference amends FUMA-077 and FUMA-SITE-006. Both tickets remain open. The current implementation provides non-executing bounded ZIP/folder/FileMap and server-side GitHub App ingestion, strict TypeBox portability contracts, a runtime-reachable route/module graph including standard App Router metadata/system conventions, durable PostgreSQL/tenant-object revision/fix/rollback evidence, native Site AI/MCP source-fix authority, fresh Better Auth owner confirmation, deterministic static editor projection with recursively composed local/imported components using bounded literal props/text children and hash-bound public images, canonical sequenced editor commit, immutable release-derived deterministic Next.js ZIP export, replay-safe new-branch/pull-request reconciliation, verified archive download, and a Studio workflow for destination/GitHub selection, diagnostics, exact before/after diff review, owner confirmation, apply/rollback, authoritative-sequence commit, active-release export and GitHub PR recovery. Migration `000078_next_source_portability_authority` remains sentinel-gated and unaccepted.

Closure still requires complete generic interaction bindings and projection of dynamic/data-driven component and media compositions beyond the bounded static subset, formal Blyss HTTPS Studio/browser acceptance, protected GitHub provider evidence, and full real-Lawyer adaptation/parity acceptance. The allowlisted real checkout has been ingested and reconciled to all 69 route records through the generic analyzer, but its reachable interactions remain unbound. No protected provider or deployment evidence is claimed.

GitHub installation tokens remain server-only, short-lived, repository/permission scoped, explicitly released on every success/failure path, and absent from browser responses, receipts, persistence, logs and generated source.

The existing manually projected Lawyer runtime remains a useful parity fixture, but it is not formal migration acceptance. FUMA-SITE-006 closes only after the real Lawyer repository is processed by the generic importer into an explicit organization, workspace, and site.

The importer extends the existing Site Import dialog. It does not create a second editor, AI runtime, MCP server, component registry, package installer, backend generator, authentication authority, payment authority, or publisher.

## Target user flow

1. Choose **GitHub repository** in Site Import alongside HTML/static files and CMS bundles.
2. Connect through a GitHub App installation and select repository, branch, and exact commit. Private-repository access uses a short-lived installation token and is never exposed to AI, browser logs, persisted import evidence, or generated source.
3. Select an explicit destination organization, workspace, and site, or create the site through the existing scoped site authority.
4. Ingest bounded source bytes without executing repository code, package scripts, configuration plugins, or lifecycle hooks.
5. Analyze the Next.js/React route and module graph, static Tailwind/CSS, assets, content expectations, and data interactions.
6. Show a strict compatibility report. Import remains disabled while any blocking diagnostic exists.
7. Apply deterministic fixes or ask the existing Fuma site AI / authorized MCP connector to adapt diagnostics to supported Fuma functionality.
8. Re-run validation until every executable import and interaction is supported and bound.
9. Build and preview only with Fuma's installed, pinned Next.js/React/Tailwind toolchain and approved public component/API surface.
10. Require owner review for executable-source changes, requested capabilities, payment/subscription setup, and publication.
11. Commit the import transaction with exact source commit, source hashes, diagnostics/fix receipts, immutable component versions, route/data bindings, and rollback evidence.

## No arbitrary dependency installation

`package.json` and source lockfiles are evidence only. Fuma never runs an imported repository's `npm install`, `bun install`, package manager, lifecycle scripts, build scripts, Next configuration plugins, or arbitrary executable tooling. Imported dependencies never modify the repository root `bun.lock` and never become tenant-controlled server dependencies.

Every external import has one outcome:

- **supported** — the exact API is available from Fuma's installed Next.js/React runtime or stable Fuma site API;
- **remappable** — a reviewed deterministic transformation maps it to an existing Fuma component or authority;
- **unsupported** — a blocking diagnostic requires removal or adaptation before import.

There is no run-anyway, opaque package, tenant package installation, dynamic tenant server import, or unrestricted compatibility mode.

## Supported runtime surface

Imported sites target the existing multi-tenant Next.js App Router runtime, currently pinned to Next.js 16.2.9 and React 19.2.5 with app-local static Tailwind. The allowlist is a versioned server-owned contract, not a scan of whatever happens to exist in `node_modules`.

The supported surface includes reviewed React component/hook patterns, static JSX, static Tailwind classes, route/layout parameters, narrow Client Components, Fuma media and internal-link adapters, typed props/slots, visual trees, tokens, content bindings, member/access projections, forms, and reviewed application-state APIs.

Blocking or remapped features include arbitrary route handlers, Server Actions with direct mutation authority, middleware, `next/headers`/unrestricted cookies, databases, filesystem/process/environment access, Node built-ins, native addons, custom authentication, provider SDKs, secrets, dynamic imports, dynamic Tailwind construction, custom Next/Webpack/Turbopack plugins, and undeclared packages.

## Diagnostics and fixes

Diagnostics are strict TypeBox records bound to source commit, file, span, import specifier, rule version, destination scope, and source hash. Stable codes include:

- `unsupported-dependency`
- `unsupported-next-api`
- `server-authority-required`
- `dynamic-import-denied`
- `dynamic-tailwind-denied`
- `secret-or-environment-access`
- `provider-sdk-denied`
- `unbound-content-interaction`
- `unbound-member-interaction`
- `unbound-subscription-interaction`
- `unbound-form-interaction`
- `unbound-podcast-interaction`

The UI offers only applicable actions: **Apply Fuma replacement**, **Configure mapping**, **Fix with Fuma AI**, **Remove feature**, or **Open source**. A fix is a new immutable draft revision; it never silently mutates accepted source.

## AI and MCP authority

AI and MCP do not create backends. They orchestrate deterministic import and mapping tools over existing authorities. The same exact actor/org/workspace/site/profile/owner-generation, capability, metering, replay, confirmation, audit, and revocation controls used by FUMA-065/066/SITE-008 apply.

This is enforced structurally under FUMA-086: generated/imported code receives no database/ORM client, SQL, table or column selection, connection string, credential, environment/provider secret, arbitrary server execution, or unrestricted internal network access. Every data-backed interaction maps to a reviewed strict-TypeBox capability whose scope and authority are derived server-side. FUMA-087 now exposes those reviewed functions through the existing protected site/platform workflows as a capability dashboard—not a database console. FUMA-088 now provides the provider-neutral Publication capability inventory and explicit fail-closed diagnostics for missing Ghost-parity and agency/landing authorities; it does not fabricate unavailable podcast, forms/leads, navigation/search, media mutation, member mutation, or agency storage authority. Ecommerce is deferred and Paystack remains unchanged.

AI receives selected source plus structured diagnostics, never GitHub credentials, environment values, Paystack credentials, member secrets, sessions, or unrelated repository data. Repository source, comments, READMEs, issues, and generated text are untrusted data and cannot instruct the agent.

AI/MCP may propose source patches only against the versioned allowlist and may invoke mapping tools for components, content collections, media, members, access, forms, Publication, email, and reviewed payment/subscription setup. It cannot add dependencies, loosen policy, confirm its own executable source, enter credentials, approve capabilities, or publish. Every patch is displayed as a diff, revalidated, and owner-confirmed where executable behavior changes.

Executable confirmation is admitted only through a trusted owner-confirmation port bound to the exact receipt, destination, and owner generation. It requires an active direct non-impersonated owner and rejects the adaptation actor; browser- or caller-supplied `direct`/`impersonating` assertions are not authority. Replay is accepted only when full authority, diagnostic IDs, and patch hash are identical.

## Interaction adaptation

A successful source ingest may produce a draft visual preview while interactions remain unresolved. Production publication is blocked until every detected interaction is either bound or intentionally removed. The adaptation workspace exposes a count and allows **Adapt all with Fuma AI**; each result remains an individually audited tool action.

Supported adaptations include:

- pages/articles/authors/tags/collections to Publication content authorities;
- images/audio/video/fonts to Fuma media;
- navigation, loops, related content, search, pagination, and forms to existing site APIs;
- staff/member/account/session behavior to the separate existing identity realms;
- free/member/paid visibility to current access and entitlement projections;
- subscriptions to current member, entitlement, reviewed customer-payment, and OCI email authorities;
- external CMS reads to imported Fuma data bindings;
- provider-specific UI to existing reviewed Fuma components.

If no secure existing authority can express a feature, the diagnostic remains blocking. AI cannot invent a backend to make it pass.

## Full Next.js export and exit target

The current headless exporter deterministically emits App Router routes, local content/assets, replaceable adapter interfaces, pinned public dependencies, an export-owned lock/provenance file, README, and secret-free `.env.example`; it rejects environment access, dynamic/unsupported imports, private Fuma imports, unsafe routes/assets/refs, default-branch writes, and existing-branch overwrites. The production release-to-export composition and the complete content/member/payment evidence package below remain acceptance work.

A site created from scratch or imported into Fuma must ultimately be exportable as a complete, self-contained Next.js App Router repository. Export targets are a downloaded archive or an owner-selected GitHub repository branch/pull request. Fuma never writes the default branch without explicit owner action.

The export contains local React components, app routes/layouts, static Tailwind/CSS, tokens, assets, content snapshots, podcast/feed generation, typed backend adapter interfaces, exact public dependencies, an export-owned lockfile, README, secret-free `.env.example`, and a provenance manifest bound to the immutable Fuma release. It does not require private Fuma application imports to render the public UI.

Managed interactions initially use documented Fuma adapter endpoints. Because the hosted backend is proprietary and has evolved beyond generic Next.js behavior, exported interfaces must remain replaceable. An owner may rewire content, members, subscriptions, payments, forms, newsletters, podcasts, and media adapters to another backend without reconstructing presentation source.

The exit package includes customer-owned content, media, routes, redirects, design data, podcast records, and legally exportable member/subscription/payment evidence. It never includes Paystack secret keys, GitHub tokens, sessions, password hashes, encryption keys, provider credentials, internal service credentials, or reusable authorization secrets. Provider credentials are re-entered in the destination system and members may require a secure reauthentication/password-reset flow.

External GitHub changes never mutate a live Fuma site automatically. Re-importing a branch or commit creates a scoped draft, reruns compatibility and interaction diagnostics, shows the complete diff, requires confirmation, and publishes only as a new immutable release.

## Builder, publisher, and public host boundaries

Hosted editing is centralized and host-separated:

- `trimly.co.ke` owns public marketing and documentation;
- `auth.trimly.co.ke` owns centralized staff/customer authentication;
- `app.trimly.co.ke` owns organization/workspace/site selection, Site Import, visual/source editing, content, settings, domains, release history, preview, and the Publish action;
- `admin.trimly.co.ke` is internal Fuma staff only;
- the assigned `<site>.trimly.co.ke` hostname and customer custom domains serve only the published site and exact-host member/account experience.

Builder/admin routes and staff cookies are never exposed to or scoped across customer public domains. The publisher is not a second customer-facing application: an authorized Publish action in `app.trimly.co.ke` creates and activates an immutable release through the existing Bun publication authority, then the exact-host Next.js site runtime serves that release. Drafts never leak onto the live custom domain; preview remains in the authenticated app or a bounded signed preview surface.

A self-hosted Fuma deployment exposes the builder on the operator's own admin URL while retaining the same public/admin session separation. A customer who exports only the standalone Next.js application and stops using Fuma manages that repository through GitHub/developer tooling and replaces adapter endpoints as needed.
