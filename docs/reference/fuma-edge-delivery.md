# FUMA-051 edge delivery

FUMA-051 adds the production boundary between FUMA-050 host resolution and immutable FUMA-049 releases. It does not add a default host, change release manifests, or move publication/member authority into the edge.

## Request and cache authority

`FreeHostService` first resolves an exact active host and release. `FreeHostEdgeBoundary` then derives an immutable edge context containing platform/organization/workspace/site owner coordinates, release, canonical path, server-owned member identity, minimized request claims, and a SHA-256 access fingerprint. Caller headers or bodies cannot choose tenant coordinates or release IDs.

Cache keys separate host, site, release, path digest, and access digest. Static anonymous HTML receives a bounded public policy. Member holes require an authenticated member, use member/access-separated private cache entries, and emit `Vary: Cookie, Authorization`. Request-scoped holes are always `private, no-store` and never enter shared cache. Content-addressed non-dynamic assets receive a one-year immutable policy. Every response carries a strong body ETag and supports exact/list/wildcard conditional GET.

## Dynamic holes

Immutable HTML may contain bounded `<!--fuma-hole:v1:<base64url-json>-->` declarations generated by `encodeEdgeHole`. The declaration names a registered resolver and strict scalar input only. PostgreSQL/object storage remains the artifact authority; reads recheck the exact active pointer, release state, manifest path, byte length, and SHA-256 before parsing holes. Resolver IDs are unique and normalized, HTML must be valid UTF-8, hole count/output and final HTML bytes are bounded, and unknown resolvers fail closed.

Resolvers receive only the immutable edge context and declaration input. They do not receive cookies, credentials, database handles, provider secrets, or caller tenant authority. FUMA-036/FUMA-039 services can be adapted behind registered request/member resolvers during central composition.

## Redis and stale control

`BunRedisEdgeCache` is ephemeral. Cache read/write outages fail open to origin rendering, but explicit purge fails closed. A Lua operation performs bounded prefix discovery and unlink atomically, so concurrent writes cannot repopulate the purged namespace during the operation. Prefixes are exact host/site or host/site/release scopes; no cross-host wildcard is accepted. HTML TTL and stale windows are bounded. Stale content is used only when origin rendering fails and only before its stale deadline.

## Rollback, purge, and warm jobs

`PostgresEdgePointerAuthority` verifies the target's immutable objects, locks the release repository transaction, requires the exact expected active pointer/current active release/target ready release, moves the active retention root, and switches the pointer with compare-and-set. A retry after process death recognizes the already-active target. The service purges the old release namespace only after the pointer switch, so new requests cannot resolve the old release; content-addressed assets remain immutable and reusable.

The complete scoped registration contains:

- `fuma.edge-purge` — exact site or release purge;
- `fuma.edge-warm` — bounded anonymous path warming;
- `fuma.edge-rollback` — expected-current rollback, old-release purge, then optional target warming.

Payloads contain no host or tenant/owner coordinates. Trusted durable-job scope and `PostgresEdgeHostAuthority` derive them server-side. Durable effect receipts make purge/warm replay-safe; rollback's pointer transition is independently idempotent.

## Acceptance

Focused acceptance covers member/access isolation, anonymous denial, request no-store behavior, conditional GET, host-separated idempotent purge, concurrent request load, exact rollback and replay, immutable assets across rollback, HEAD/ETag/Vary/release headers, durable-job replay, and a deterministic warm → purge → member hole → rollback demo. The architecture gate preserves TypeBox-only contracts, bounded Redis purge, integrity checks, pointer CAS, authority-free job payloads, and conductor-owned central mounting.
